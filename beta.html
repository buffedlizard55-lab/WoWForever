Beta observation · snapshot 2026-09-19

The beta observation log

The beta is the last window in which a class claim can be improved before launch — and the window in which Blizzard has said it will change class balance. This page dates that window, shows exactly which claims could be upgraded, and states plainly that none of them has been observed first-hand by this project yet. It exists so a future session can do the work without inventing any of it.

Status of this log: empty on purpose.

No row below has been marked observed, because observing means running the beta client and capturing the result — which this project has not done. Every class claim it holds is still guide or datamine evidence, which is precisely why Class PvP carries no ranking.

What the beta cannot settle. A level-20 or level-30 cap means no level-60 talents, no level-60 gear, no raids and — until Blizzard enables it — no rated PvP. Class material gathered in the beta is useful for rotations, ability text and bugs; it is not a level-60 performance measurement, and this site will not present it as one.

The reported → observed rule

  1. Client access first. Without the beta client, no row can be upgraded, and the log says so rather than borrowing someone else's observation as if it were a measurement.
  2. Name the build. Forever's patch numbering is 1.60.x — Auctionator's Forever-capable release declares “Supported Classic Forever patch1.60.1” and Wowhead tags its Forever pages “Patch 1.60.1”; an observation without a build number cannot be reproduced. Wago listingWowhead
  3. Capture the state. Ability text, talent tree state and the level at which each was seen — a screenshot or an in-game export, not a memory.
  4. Add a ledger row. New evidence becomes a claim with a snapshot date, citing the capture; the older guide-based claim keeps its ID and gains a note.
  5. Change the chip on the profile. The class row moves from guide to observed evidence, and the profile says who observed it and when.
  6. Re-check at each build. A beta build can invalidate an observation; the weekly source watcher already watches the pages these claims rest on.

Why the bar is this high. A class claim that cannot be reproduced is indistinguishable from a guess, and the site's whole promise is that a reader can check every statement. Being slow here is the feature.

Why class claims are expected to move

Blizzard's own statement

Asked about class design before the beta, the developers said: “In the beta, we're going to look at class balance now that some classes have new spells, and we'll make adjustments where necessary.” IGN Nordic

That is a statement of intent, not a tuning list. It means the balance picture is expected to change during the test, so any class comparison written before it is provisional by the publisher's own admission (C151, C152).

No Forever tuning changelist yet

Two days into the beta, no Forever class-tuning changelist had been published. The only dated tuning post in the adjacent feed belongs to modern WoW's patch 12.1.0 (C157, C159).

Recorded as an observation with a date, so that a later session can show when the situation changed rather than assuming it never did.

Dated known-issues monitoring

Blizzard's beta known-issues list is the most useful dated document the beta produces, because it names mechanics that are currently wrong rather than simply unfinished. It is a moving list, so it is treated as dated material.

  • Last read: 19 September 2026 (the 18 September edition is still the current one) — caster and higher-level melee Glancing Blow maths, pet-stat display, consumable and buff armour multiplying with Bear Form, On-Next Attack abilities disabling the spell-queue window, and class-varying Cooldown Manager work in progress; the topic's later update adds that Pet Expertise is not displayed for Hunters and Warlocks (C143). Blizzard forum postWowhead mirrorIcy Veins
  • Why it matters to PvP: Glancing Blow maths and spell-queue behaviour are exactly the mechanics that decide melee-versus-caster outcomes, so any battleground impression formed while they are broken is not evidence about final balance.
  • Next check: (1) whether a later dated post replaces it, and (2) whether each listed item is resolved — the source watcher fingerprints the page and will flag a change, but only a human can read which line moved.

A known issue is not a preview. The list describes current defects. Nothing on this site may be rewritten on the assumption that a listed bug will be fixed in a particular way.
