  • Explicit gap documentation for every PvP, BiS and economy number that is still unpublished.
  • A no-hallucination contract: any statement without a source is either labelled our reasoning or moved to the “not announced” set.
  • Per-class PvP profiles — nine PvP-only profiles with an evidence chip and source link on every row, a one-line summary table, an explicit “no ranking” contract, a pre-beta warning, and a verified per-class reading list.
  • Add-on and tooling tracker — dated status for Auctionator, TradeSkillMaster, Questie, Details! and WeakAuras, built on a new tooling evidence class so software metadata can never be presented as a game fact.
  • Beta observation log — the dated beta calendar, per-class observation status (all nine marked not observed, because they are), the reported → observed upgrade rule, and three false positives that would otherwise become fake facts.
  • Market log scaffold — data/market-log.csv with a documented schema, a written first-row procedure and deliberately zero data rows until an auction house exists (0 rows today), validated against the Gold page watchlist.
  • Ten machine checks now gate the repository — tools/check-ledger.mjs (integrity, staleness), tools/check-citations.mjs (registered sources, resolving anchors, canonical and sitemap agreement, claim IDs, tag balance, machine-checked self-reported counts, and evidence-class documentation), tools/check-market-log.mjs (schema, with a hard refusal of any pre-launch price row), tools/check-apis.mjs (endpoint eligibility and limits), tools/check-patterns.mjs (dated, registered site patterns), tools/check-quotes.mjs (no quotation may sit far from a source), tools/check-a11y.mjs (landmarks, headings, captions, labels, focus, reduced motion, print), tools/test-render.mjs (every JS-rendered table fills), tools/test-source-watch.mjs and tools/test-watch-feeds.mjs (offline fixture tests of the two watchers). .github/workflows/verify.yml runs them on every push and pull request.

Feeds that change by design are marked watch: false in the registry so the text-fingerprint watcher no longer reports them as “changed” every week. tools/test-watch-feeds.mjs proves the logic offline and fails if any feed URL is not a registered source. First real run: the next push to main (the workflow's preflight now runs when either baseline file is missing) or Monday 21 September, 07:00 UTC.
  • All five open project decisions taken and implemented; see Decisions.

The source-watch baseline

A fingerprint baseline is the record of what each cited page looked like the first time we checked it. Until it exists, change detection has nothing to compare against. This is the one deliverable the authoring environment cannot produce by itself.

Why the runner had to create it, not this environment

  • The shell has no direct outbound network. Re-confirmed in the live-web pass: requests to the registered hosts still fail at the TLS handshake from the shell, so node tools/check-sources.mjs --dry-run reports every URL unreachable and cannot produce the baseline. That is an environment limitation, not evidence that the pages are dead — this pass read the same pages successfully through the platform's research tools, which is how every source below was verified.
  • This session's GitHub token cannot dispatch workflows. gh workflow run returns HTTP 403 “Resource not accessible by integration”, so the baseline could not be triggered from here either. The fix was to stop depending on a dispatch: the workflow itself now runs when a push to main happens and no baseline exists.

How the baseline gets created, and what proves it will work

  • Scheduled: the Action runs every Monday at 07:00 UTC and always runs on main.
  • By hand: a maintainer with the repository's own token can run gh workflow run source-watch.yml --ref main -f init=true, or use “Run workflow” in the Actions tab with Baseline only ticked.
  • Automatically: a preflight job lets the workflow run on a push to main only when tools/source-state.json is missing. So a baseline that is lost — or never created, as here — repairs itself on the next push to main, and ordinary pushes never pay for a network run.
  • The watcher's behaviour is now machine-tested offline (tools/test-source-watch.mjs): a first run writes a baseline and files no issue; an edited page is reported; a previously reachable page that stops responding is reported as a regression and keeps its old fingerprint; a runner that can reach nothing writes no baseline at all and fails the job loudly, so a broken runner cannot silently become an empty “baseline” that later runs compare against.

What the first run will do. It records every reachable source as newly baselined (no issue is filed for that), commits tools/source-state.json, and prints a step summary with the counts. If it reports zero reachable sources, the job fails on purpose: that means the runner itself is blocked and the citations need another route, not that the whole citation set is dead.
