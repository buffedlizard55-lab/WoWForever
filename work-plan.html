Work plan · snapshot 2026-09-18

What still needs doing — and what is genuinely blocked

This page is the project's honest backlog. It separates blocked work (cannot be done correctly until Blizzard or the live economy produces data) from available work (can be done now), and schedules both against dates the game itself has published.

Delivered so far

  • Sourced site covering roadmap, PvP, classes, gear/BiS status, gold and market mechanics, each on its own page.
  • Machine-readable source registry (data/sources.js) and claims ledger (data/claims.js) with evidence classes and snapshot dates.
  • Public irregularity log (I-1 to I-6) including fabricated tier-list detection and the resolved dungeon-range conflicts.
  • Explicit gap documentation for every PvP, BiS and economy number that is still unpublished.
  • A no-hallucination contract: any statement without a source is either labelled our reasoning or moved to the “not announced” set.
  • A second verification round: 42 registered sources and 74 ledger claims (IDs C001–C110), including the datamined 14-rank reward table, the Legacy reward track, the pre-order/paywall facts, and a coverage audit of what the big guide sites actually publish for Forever (C103–C109).

Phase 1 — next session, before 4 November

Source completion (highest value first)

  1. Read and ledger the remaining Blizzard first-party pages line by line: the pre-purchase article, the Found Photos recap, and the official news index for any Forever post since 18 September.
  2. Read the outstanding Wowhead interview summaries we have only cited second-hand: New Biome Buff Gear (IGN Nordic), No Raid Attunements (But Why Tho?), Dungeon Experience Changes (The Sun), Official Controller Support & Mount Skill Costs (Sportskeeda), and the beta known-issues blue posts.
  3. Complete the Wowhead racials guide and the Warcraft Wiki article chunk-by-chunk, then convert every extracted fact into ledger rows.
  4. Read the remaining Icy Veins race guides (Dwarf, Gnome, Human, Night Elf, Orc, Troll, Undead, Skyborne) and record the Classic-to-Forever racial diffs.
  5. Work through the remaining Wowhead Forever guides (14 of the 17 had not been read line-by-line at this snapshot) and ledger each fact.
  6. Verify the pre-order pack windows and the early name-reservation dates from Blizzard's own shop pages rather than the guide summary.

Site work

  1. Addon compatibility tracker — a dated table of which addons publish Forever builds (TSM, Questie, Details and others), re-checked every update.
  2. Per-class profile pages — one page per class using only verified abilities and racial interactions, with a “no PvP ranking yet” banner.
  3. Ability capture log — for each class, record what is testable at 20 and 30 in the beta, with the trainers/talents that define it.
  4. Ledger tooling — a small script that lists claims whose snapshot date is older than N days, so stale facts surface automatically.
  5. Accessibility and print pass — verify every table reads correctly on mobile and in print for manual review.

Phase 2 — launch window, 4 November onward

Data pipeline

  • Stand up the level-60 item verification pipeline described on the Gear page: item ID, stat block, drop source, phase, permalink, verification date.
  • Publish pre-raid gear tables per class, split by armour type and role, with acquisition links only from the Forever namespace.
  • Begin the market baseline log: daily minimum buyouts for the watchlist items on the Gold page.
  • Record which price addons actually function on Forever clients, then document a verified workflow.

PvP work

  • Record battleground availability the moment the live client confirms it, replacing the current “implied only” status.
  • Collect Honor gain observations from real battlegrounds to replace the unpublished numbers with measured ones — clearly labelled as observed, not official.
  • Stand up battleground-role notes per class as play begins, using the published methodology on the Classes page.

Phase 3 — raid window, 9 December onward

  • First defensible BiS lists — pre-raid and phase-1 raid sets, each item source-verified, with the previous version retained.
  • Crafted tier-set economy — track Malleable Essence of Nature supply, Guardians of Hyjal reputation gating, and the BoE crafted-piece market as it forms.
  • First PvP value assessment — battleground-role based, minimum-sample enforced, version-stamped, with the evidence for every placement.
  • Legendary and chase-item documentation — Blizzard has teased a legendary reward and every raid boss having chase items (press); document them when they are live.

Decisions requested

These are judgement calls where the project needs a human answer; each has a default we can continue with if no answer arrives.

DecisionOptionsDefault if unanswered
How aggressive should launch coverage be? (a) Publish only verified item sources; (b) also publish clearly-labelled community-reported drop rates with a “reported” tag. (a) — verification first; reported data can be added later behind a visible tag.
Do we add automated source polling? (a) Keep everything manual; (b) add a scheduled GitHub Action that checks registered URLs for changes and opens an issue with a diff. (b) is recommended and cheap, but requires approval because it adds a workflow to the repository.
PvP tier list timing (a) Wait for a full season of data; (b) publish a provisional, explicitly-labelled assessment after launch week. (a) — the project's credibility rests on not repeating the noise it criticises.
Market logging effort (a) Manual daily log of the watchlist; (b) recruit volunteers; (c) no logging until tooling exists. (a) for the watchlist only — small, bounded, and verifiable.
Scope of class profiles (a) One page per class covering PvE and PvP; (b) PvP-only profiles. (b) matches the project's stated focus, with PvE notes only where they affect gearing.
