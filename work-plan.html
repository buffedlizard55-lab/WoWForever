What still needs doing — and what is genuinely blocked

This page is the project's honest backlog. It separates blocked work (cannot be done correctly until Blizzard or the live economy produces data) from available work (can be done now), and schedules both against dates the game itself has published.

Delivered so far

  • Sourced site covering roadmap, PvP, classes, gear/BiS status, gold and market mechanics, each on its own page.
  • Machine-readable source registry (data/sources.js) and claims ledger (data/claims.js) with evidence classes and snapshot dates.
  • Public irregularity log (I-1 to I-8) including fabricated tier-list detection, the resolved dungeon-range conflicts, and cross-version contamination on Forever item pages.
  • Explicit gap documentation for every PvP, BiS and economy number that is still unpublished.
  • A no-hallucination contract: any statement without a source is either labelled our reasoning or moved to the “not announced” set.
  • A second verification round: the datamined 14-rank reward table, the Legacy reward track, the pre-order/paywall facts, and a coverage audit of what the big guide sites actually publish for Forever (C103–C109).
  • Third round (this session): 49 registered sources and 90 ledger claims (IDs C001–C126). All nine Icy Veins class overviews and Blizzard's three panel recaps were read in full and converted into per-class rows; the Wowhead coverage audit was re-run and its result corrected in place rather than silently edited (C107).
  • Per-class PvP profiles — nine PvP-only profiles with an evidence chip and source link on every row, a one-line summary table, and an explicit “no ranking” contract (C111–C121).
  • Automated source watching — a weekly GitHub Action fingerprints every registered URL and opens an issue when a cited page changes or dies (tools/check-sources.mjs).
  • Ledger tooling — tools/check-ledger.mjs fails on dangling source ids, duplicate ids, invalid evidence classes, malformed snapshot dates and sourceless claims, and lists claims older than N days.
  • Market log scaffold — data/market-log.csv with a documented schema and deliberately zero data rows until an auction house exists.
  • All five open project decisions taken and implemented; see Decisions.

Phase 1 — next session, before 4 November

Source completion (highest value first)

  1. Read and ledger the remaining Blizzard first-party pages line by line: the pre-purchase article, the Found Photos recap, and the official news index for any Forever post since 18 September.
  2. Read the outstanding Wowhead interview summaries we have only cited second-hand: New Biome Buff Gear (IGN Nordic), No Raid Attunements (But Why Tho?), Dungeon Experience Changes (The Sun), Official Controller Support & Mount Skill Costs (Sportskeeda), and the beta known-issues blue posts.
  3. Complete the Wowhead racials guide and the Warcraft Wiki article chunk-by-chunk, then convert every extracted fact into ledger rows.
  4. Read the remaining Icy Veins race guides (Dwarf, Gnome, Human, Night Elf, Orc, Troll, Undead, Skyborne) and record the Classic-to-Forever racial diffs.
  5. Work through the remaining Wowhead Forever guides (14 of the 17 had not been read line-by-line at this snapshot) and ledger each fact.
  6. Verify the pre-order pack windows and the early name-reservation dates from Blizzard's own shop pages rather than the guide summary.

Site work

  1. Addon compatibility tracker — a dated table of which addons publish Forever builds (TSM, Questie, Details and others), re-checked every update.
  2. Per-class profile pages — one page per class using only verified abilities and racial interactions, with a “no PvP ranking yet” banner.
  3. Ability capture log — for each class, record what is testable at 20 and 30 in the beta, with the trainers/talents that define it.
  4. Ledger tooling — a small script that lists claims whose snapshot date is older than N days, so stale facts surface automatically.
  5. Accessibility and print pass — verify every table reads correctly on mobile and in print for manual review.

Phase 2 — launch window, 4 November onward

Data pipeline

  • Stand up the level-60 item verification pipeline described on the Gear page: item ID, stat block, drop source, phase, permalink, verification date.
  • Publish pre-raid gear tables per class, split by armour type and role, with acquisition links only from the Forever namespace.
  • Begin the market baseline log: daily minimum buyouts for the watchlist items on the Gold page.
  • Record which price addons actually function on Forever clients, then document a verified workflow.

PvP work

  • Record battleground availability the moment the live client confirms it, replacing the current “implied only” status.
  • Collect Honor gain observations from real battlegrounds to replace the unpublished numbers with measured ones — clearly labelled as observed, not official.
  • Stand up battleground-role notes per class as play begins, using the published methodology on the Classes page.

Phase 3 — raid window, 9 December onward

  • First defensible BiS lists — pre-raid and phase-1 raid sets, each item source-verified, with the previous version retained.
  • Crafted tier-set economy — track Malleable Essence of Nature supply, Guardians of Hyjal reputation gating, and the BoE crafted-piece market as it forms.
  • First PvP value assessment — battleground-role based, minimum-sample enforced, version-stamped, with the evidence for every placement.
  • Legendary and chase-item documentation — Blizzard has teased a legendary reward and every raid boss having chase items (press); document them when they are live.

Decisions — resolved this session Project policy

All five open decisions were taken on 2026-09-18 and implemented in this repository. Each row records the choice, what shipped, and how to reverse it. These are editorial policies, not game facts; they are in the ledger as claim C122 so the site's own rules are auditable alongside its claims.

Decisions taken, with the artefact that implements each one.
DecisionChosenWhat shippedHow to reverse
Launch-coverage aggressiveness
Verified sources only, or also community-reported drop rates?		 (a) Verification first, with community-reported data admitted later only behind a visible reported tag and never mixed into a verified table. The rule is enforced by the ledger: a claim needs a registered source and an evidence class, and tools/check-ledger.mjs fails the build if either is missing. A community evidence class already exists for flagged material. Admit reported data by adding rows with status: "community" — they will render with the red flag chip automatically, so it cannot be done quietly.
Scheduled URL-watch Action
Manual re-checking, or automated polling?		 (b) Add the Action. It checks whether cited pages moved; it never edits site content. .github/workflows/source-watch.yml runs tools/check-sources.mjs every Monday at 07:00 UTC (and on demand). It fingerprints every registered URL with volatile page chrome stripped — scripts, styles, relative timestamps, counters — then opens an issue listing changed and unreachable sources. Fingerprints live in tools/source-state.json; a failed fetch preserves the previous baseline so an outage cannot silently reset it. Delete the workflow file. The checker also runs locally: node tools/check-sources.mjs --dry-run.
PvP tier-list timing
Wait for a season, or publish provisionally after launch week?		 (a) Wait for a full season. No tier, grade or score is published before then, under any label. The new Class PvP profiles page ships the useful half of a tier list — published, sourced, battleground-relevant mechanics per class — with an explicit “no ranking” contract and the methodology published in advance on the Classes page. Not reversible without breaking the project's stated rule. A provisional assessment would require publishing the sample size, gear level and build it was measured at.
Market-logging effort
Manual daily log, volunteers, or wait for tooling?		 (a) Manual, watchlist only. Small, bounded, and verifiable by one person. data/market-log.csv exists with a documented schema (date, faction, item, item id, quantity listed, minimum buyout in copper, observer, evidence link, note) and zero data rows — because no auction house exists before 4 November 2026. The watchlist it serves is justified item-by-item on the Gold page. Widen the watchlist, or switch to volunteers by adding an observer convention and a review step.
Scope of class profiles
PvE and PvP, or PvP-only?		 (b) PvP-only, with PvE notes only where they affect gearing or are the source of the ability described. Nine profiles, one per class, each row carrying an evidence chip and a source link, plus a one-line summary table for quick reading and a per-class “still unknown” column. Ledger claims C111–C121. Add PvE sections per class; the page structure already separates “published change” from “why it matters in a battleground”.

Why the defaults were adopted rather than overridden. Four of the five defaults were the conservative option and nothing found during this session's verification pass argued against them. The one that required approval — the scheduled Action — was adopted because it only detects change and files an issue for a human; it cannot publish, edit or re-date a claim. That boundary is what makes automation compatible with a no-hallucination rule.
