Data sources · snapshot 2026-09-19

Public endpoints this project is allowed to use

The brief allows a free API key that anyone can obtain without registering, and rules out anything that needs an account, a signup or a tier. This page is the register: every endpoint was fetched, the response is described, and the candidates that failed the test are recorded with the evidence for the refusal — including Blizzard's own game APIs.

The finding, in one line.

Blizzard's forums and Blizzard's build service both answer a plain request with no credential at all, so a Forever beta build moving or a blue post landing can be noticed without asking anyone's permission. Blizzard's game data APIs cannot: Blizzard's own documentation requires an account, an authenticator and an OAuth client before the first request is served (C194).

Tested on 19 September 2026. Each decision is a ledger claim with a source, so it can be re-checked by hand: forum feedbuild servicedeveloper docs

Update, later on 19 September 2026: the Forever beta's build is now readable. Blizzard's version service publishes a product summary that lists every product code; reading it (instead of guessing) showed that the code wowf exists but serves no versions, and that the product wow_classic_beta served build 1.60.1.69913 to us, eu, kr and tw that day (C211). The identification of that product as the Forever beta is our reasoning, kept separate and falsifiable (C212) — see the build note below.

The eligibility rule

Three tests, applied before an endpoint is touched. A source has to pass all three, and the tests are written to be checkable by a reader rather than to be flattering to this project.

The three tests a data source must pass, and what each one excludes. Recorded in data/apis.js.
TestWhat it demandsWhat it excludes
No secret required The endpoint answers a plain request. If a credential is needed at all, it must be one anyone can generate without an account. Endpoints that only answer with a token, and anything that expects a personal key to be pasted into a page.
No account, no registration No Battle.net account, no developer portal client, no OAuth application, no two-factor enrolment, no acceptance of a developer agreement before the first byte comes back. Blizzard's Game Data and Community APIs, and any service that gates its documentation or its data behind a login.
No free-tier gate Public use that does not depend on a paid plan, a commercial licence, a partner agreement, or a permission the provider can withdraw to make this site stop working. Freemium APIs whose useful rate needs registration, and licences that forbid or restrict the way the data would be shown here.

What happens when something fails. It is not used, and the gap is published instead — the same rule this site applies to unpublished Honor values and hidden item stats. Every source on every page is a public page a reader can open in a browser without registering; that is why the site has no automated price or character feed, and why the market log is designed around dated human observations with permalinks.

Verified and in use

Each row was fetched on the date shown with no credentials of any kind. What came back is a description of the actual response, not a summary of a documentation page. These endpoints are registered as sources as well (8 of them here, 119 sources in total), so the citation checker covers each one and this page cannot quietly grow a URL nobody checks. Pages are fingerprinted weekly; feeds that change by design (topic lists, build manifests) are instead read semantically each week by tools/watch-feeds.mjs, which reports a build change as old → new and a staff-touched forum topic with its thread link.

A machine-readable endpoint is not a better source than a page. The forum feed tells this project that a thread exists; it does not say whether the poster is Blizzard staff, and it cannot distinguish a blue post from a player argument. Every forum-derived statement is opened on the thread page and checked against the blue-tracker listing before it is recorded — the feed makes discovery cheap, and changes nothing about the evidence standard.

What this changes — and what it does not

Now watchable without a credential

  • Client builds — including the Forever beta's. A build number straight from Blizzard, dated when read — the cheapest possible answer to “did the beta move today?” (C192). Since 19 September that includes the wow_classic_beta product, 1.60.1.69913 that day (C211, identification C212).
  • New Forever forum topics, and staff posts in them. Category feeds scoped to Forever (346) and to the Forever beta (349), whose user records carry Blizzard's own community-manager marker, so a blue reply can be flagged for a human to open the day it lands (C190, C191, C216).
  • Product codes going live. The summary shows which codes carry a versions record; the day wowf gains one is the day the weekly report says so (C193).
  • Add-on declarations. A release listing's game-version chips can be cross-checked against Blizzard's build service instead of being taken on trust — Auctionator's “Classic Forever 1.60.1” chip matches the wow_classic_beta line (C197).

Still impossible under the rule

  • Prices. No auction house exists before 4 November 2026, and no public price endpoint will exist after it without a credential (C194).
  • Characters and items. No armory-style feed, so no automated Best-in-Slot verification and no per-character checks.
  • Loot tables. Item stats stay hidden until a drop is recorded (C062), which no endpoint can work around.

One consequence is worth stating on its own. The project's market work is a human workflow by construction, not by preference: a price observation has to be captured by hand, dated, and tied to a permalink, because the alternative would be an API key this rule does not allow — and, more importantly, an account that a reader cannot check.

How the register stays honest

  • Fetched, not assumed. An endpoint is listed as verified only after a plain request came back, on a stated date, and the response is described. Two guessed URLs for a Forever build returned no data and were published as a gap (C193) rather than papered over; the gap closed the same day only because the service's own product list was read instead of guessed again (C211).
  • Read, never named. The build service never says “Forever”. The number is always printed as “the wow_classic_beta build on date”, and the reasoning that ties it to Forever stays a separate, falsifiable claim (C212).
  • Registered as a source. Every verified endpoint is also in data/sources.js, so the citation checker covers it; pages are fingerprinted weekly, feeds are read semantically weekly, and a change in behaviour surfaces as an issue instead of a silent break. The offline test tools/test-watch-feeds.mjs fails if a feed URL is not a registered source.
  • Limits are mandatory. Each verified row states what the endpoint must never be used for. An endpoint with no stated limit is treated as unusable.
  • Status changes are claim changes. If an endpoint starts requiring a key, the claim that cites it is superseded with a new date, in the same way the ledger handles every other correction.

The full machine-readable register is data/apis.js; the checks that enforce it are tools/check-apis.mjs (schema, eligibility flags, and that a rejected URL never appears as a link) and tools/check-citations.mjs (that every URL linked here is a registered source).
